# Sales Analytics Pipeline & Dashboard

A small, end-to-end business-analytics project: raw sales CSV → **Java ETL** (validate + clean) → **star-schema MySQL database** → **SQL KPI views** → **interactive dashboard** (Chart.js, or Power BI on the same views).

```
raw_sales.csv ──► Java ETL ──► star-schema CSVs ──► MySQL 8 (schema.sql)
 (dirty data)     clean +        + rejects.csv            │
                  validate                                ▼
                                                   SQL KPI views (kpi_views.sql)
                                                          │
                                  ┌───────────────────────┴──────────────┐
                                  ▼                                      ▼
                       Power BI / any BI tool                  dashboard/index.html
                       (connect to MySQL views)                (Chart.js, demo mode)
```

## Quick start (no MySQL needed)
Requires Java 17+, Python 3.9+. (Node.js only for the optional dashboard test.)
```bash
./build_and_run.sh          # clean data -> star schema -> KPI views -> dashboard/data.js
# then open dashboard/index.html in a browser (needs internet once, to load Chart.js from a CDN)
./run_all_tests.sh          # full test suite
```
`dashboard/data.js` is already generated, so `index.html` opens immediately.

## Using MySQL 8+
```sql
CREATE DATABASE sales;
```
Download the MySQL Connector/J jar, then:
```bash
java -cp build/classes:mysql-connector-j-8.x.jar salesetl.Main \
  --input data/raw_sales.csv --out out \
  --mysql-url "jdbc:mysql://localhost:3306/sales" --user root --password "$DB_PASSWORD"
```
This creates the tables, loads them, and creates the eight `v_*` views. In Power BI: *Get data → MySQL database → select the `v_*` views*.

## Star schema
```
dim_date ─┐
dim_customer ─┤
dim_product ──┼──► fact_orders (quantity, unit_price, discount, revenue, cost, profit)
dim_region ───┘
```
`revenue = quantity × unit_price × (1 − discount)`, `profit = revenue − quantity × unit cost` (BigDecimal, rounded half-up to 2 places).

## SQL KPI views (`sql/kpi_views.sql`)
| View | Answers | Techniques |
|---|---|---|
| `v_kpi_summary` | revenue, profit, margin, orders, customers, AOV | aggregates, COUNT DISTINCT |
| `v_monthly_trend` | monthly revenue/profit, MoM growth %, running total | CTE, `LAG`, running `SUM() OVER` |
| `v_weekly_trend` | ISO-week trend | joins, GROUP BY |
| `v_top_products` / `v_top_customers` | rankings | `RANK() OVER` on an aggregate |
| `v_region_performance` | revenue, margin, avg discount, share of total | `SUM(SUM()) OVER ()` |
| `v_category_profit` | category margins | joins |
| `v_discount_vs_profit` | margin by discount band | derived table + `CASE` |

## Data cleaning rules (what the ETL rejects)
Rows are rejected with a reason written to `out/rejects.csv`: `missing_field`, `bad_date` (accepts `yyyy-MM-dd` and `dd/MM/yyyy`, strict, so 31 Feb fails), `bad_quantity` (≤ 0 or non-integer), `bad_price`, `bad_discount` (outside 0–1; blank = 0), `bad_cost`, `duplicate` (same order + product; first wins). Region text is trimmed and title-cased.

## Findings on the included sample data
The sample data is **synthetic** (generated by `data/generate_sample_data.py`, seed 42, with deliberately dirty rows), so these findings describe the sample, not a real business. Of 2,376 raw rows, 2,293 were loaded and 83 rejected.
- Overall: revenue 1,052,189, profit 196,935, margin 18.7%.
- **West** brings 27.9% of revenue but only a 6.8% margin; its average discount is 22.0% against about 6% elsewhere.
- Margin falls with discount depth: 27.4% with no discount, 9.7% at 11–20%, and **−3.3%** above 20% (those lines lose money overall).
- Technology is 65% of revenue but has the lowest category margin (15.5%).

## Testing (`./run_all_tests.sh`)
| Layer | What it checks |
|---|---|
| Java (83 checks, no dependencies) | CSV parsing, every cleaning rule and edge case, money rounding, star-schema keys, ISO week at year boundary, end-to-end file output |
| Python + SQL (23 tests) | Java output loaded into SQLite with the same `schema.sql`/`kpi_views.sql`; every KPI view compared with an independent Python re-implementation; referential integrity; formulas; hand-computed tiny datasets; empty-table safety; re-run idempotence |
| Dashboard (Node) | Runs the page script against a stub DOM/Chart: charts drawn, toggles work, finding computed from data, graceful errors when `data.js` or Chart.js is missing |

I also verified the tests by deliberately breaking the code (rounding, dedupe, profit sign, rank order, MoM formula, wrong join, discount-band edge, ISO week); every break was caught.

**Known limits:** the MySQL loader (`MySqlLoader.java`) was not run against a live MySQL server in the build environment; the SQL is written in the portable subset shared with SQLite and loading is a plain batched `INSERT`, but run it once against your own MySQL and tell me if anything breaks. The dashboard layout was not checked visually in a browser.
